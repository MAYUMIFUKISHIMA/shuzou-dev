# Supabase接続と本番前の確認

コードとSQLは準備済みですが、この環境には会社のSupabase URL/公開キーがありません。実サービスでの認証・DB/API接続は未検証です。以下は管理者が会社管理のプロジェクトで行う初期設定です。

## 初期設定
1. 会社管理のSupabaseプロジェクトを作成する。まず検証用データだけを使う。
2. `supabase/migrations/202610300001_records.sql`をSupabaseのマイグレーション手段またはSQL Editorで一度適用する。既存の同名テーブルがあれば上書きせず確認する。
3. Authentication設定で公開サインアップを無効にする。管理者が個人のユーザーを作成し、個人メールアドレスとパスワードでログインできるようにする。メール配送・招待・パスワード再設定はSupabase側で確認する。アプリ内にはパスワード再設定画面はまだない。
4. 作成されたユーザーIDを使い、SQL Editorからprofilesを登録する（値は実ユーザーに置換）。

```sql
insert into public.profiles (id, role)
values ('実ユーザーのUUID', 'worker');
-- 管理者のみ role を 'admin' とする。
```

役割はユーザーメタデータに依存せず、一般ユーザーから変更できない。管理者の追加・変更はSQL管理者が行う。

5. `.env.example`を参考にローカルの`.env.local`またはホスティングの環境変数に以下を設定する。公開用の値のみを使用する。
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_PUBLISHABLE_KEY`（publishable key。service_roleやsecret keyは禁止）
6. クラウド環境の制限付きネットワークに、プロジェクトの正確なホスト名 `プロジェクトID.supabase.co` を追加する。現在はホスト名未確定のため、許可先を推測して追加していない。
7. `npm run build`を実行し、生成したdistをHTTPSで提供する。Vite環境変数はビルド時に組み込まれるので、変更後は再ビルドする。デプロイ先の作成・一般公開は未実施。

## 使い方
設定がなければ従来のデモ画面、両方設定されるとログイン画面になる。端末保存→「未送信分を送信」でサーバー受付を確認してからキューを削除する。接続復帰・ログイン後にも再送する。失敗や応答不明の場合はIDを変えず再送し、二重登録を防ぐ。

管理者は一覧・修正・変更履歴・削除・復元・CSV/JSON出力・社内保存確認を操作できる。一般作業員は自分の有効な記録だけを閲覧・修正できる。サーバー側RLSとRPCで権限を強制する。

## 共用端末と圏外
- ログイン状態はSupabase SDKのlocalStorageに保存し、タブ間で同期する。共用端末を交代するときは必ずアプリの「ログアウト・交代」を使う。セッション期限切れや新しい作業員の認証はオンラインで行う。
- 未送信記録はIndexedDB。前の利用者の記録があれば、明示的な破棄確認なしに別利用者へ渡さない。
- 同期・破棄はWeb Locksで直列化する。最新Chrome/AndroidとHTTPSが必要。
- PWAは本番ビルドで有効。初回にオンラインで読み込み、Service Workerが準備された後はアプリ本体を圏外でも開ける。初回の圏外起動はできない。
- Service Workerはアプリの静的ファイルだけをキャッシュし、認証応答やAPIデータはキャッシュしない。
- ブラウザのストレージ消去、端末紛失、容量回収による未送信記録消失は防げない。保存前のフォーム入力はタブ・画面切替で失われる。

## CSVと保存期間
出力は全記録・履歴を固定したスナップショット。CSVは表計算用に数式を無害化し、JSONは元の文字列・履歴・ID・改訂を保存する。両方を会社の保存先へ移して内容を確認後、社内保存確認を押す。確認後の修正は古い出力に反映されず、再出力が必要。

**自動物理削除は有効化していない。** 製造完了日、混合分割の関係、保存済み最新版の判定が帳票から確定するまでは、1年経過の推測によって削除しない。24時間の復元期限はサーバーで強制するが、期限後も削除済みデータは物理的には残る。履歴・出力スナップショット・Supabaseバックアップにも別途保存期限の設計が必要。

## 本番前に必要な検証
実Supabase上で作業員2人と管理者1人による権限・ログアウト・通信失敗・再送を確認。実機AndroidでPWA、端末容量不足、圏外からの復帰を確認。帳票とCSV項目を確定し、バックアップの取得・復元、無料枠の容量と利用条件を確認してから実業務へ移行する。
